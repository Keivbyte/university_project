# Математика — этап 5

Header-only C++20, пространство имён `math`, компоненты `float`.
Зависимости реализации: только стандартные `<cmath>` и `<cassert>`.

## Соглашения

- `Mat4`: column-major, индекс `column * 4 + row`, доступ через `(row, column)`.
- Векторы-столбцы: `M * v`. `T * R * S * v` сначала масштабирует, затем вращает,
  затем переносит. Точка имеет `w = 1`, направление — `w = 0`.
- Правосторонняя система: +X вправо, +Y вверх; исходное направление камеры −Z.
  Положительные вращения следуют правилу правой руки. Углы в радианах.
- Векторы и матрицы по умолчанию нулевые. Единичная матрица — `Mat4::identity()`.
- `==` точное; `nearlyEqual` использует абсолютный и относительный допуски.
- `normalize` возвращает новый вектор. Нефинитные компоненты и длина ≤ 1e-6
  вызывают assert в Debug; при `NDEBUG` функция возвращает нулевой вектор.
  Масштабирование перед нормализацией предотвращает промежуточное переполнение.
- Индексы должны быть в диапазоне, делители — ненулевыми. Обычная арифметика
  остаётся арифметикой float: `dot` и `lengthSq` могут переполняться.
- `clamp` требует `low <= high`; `lerp` не ограничивает параметр диапазоном [0, 1].

## Файлы и контракт

- `utils.h`: константы, radians/degrees, min/max, clamp, lerp, nearlyEqual.
- `vec.h`: Vec2/3/4, арифметика со скалярами с обеих сторон и покомпонентно,
  составные операторы, индексация, dot, cross для Vec3, length/lengthSq,
  normalize, distance, lerp.
- `mat.h`: identity, translation, scale, rotationX/Y/Z, умножение, transpose.
- `geometry.h`: Ray, AABB, Plane без алгоритмов пересечений.

Ray требует единичное направление (по умолчанию −Z). Plane задаётся уравнением
`dot(normal, point) + distance = 0` с единичной нормалью; положительное значение
`signedDistance` находится со стороны нормали. По умолчанию это плоскость y=0.
При нормализации коэффициентов плоскости нужно делить и нормаль, и distance.

AABB требует конечные упорядоченные границы. `contains` включает границы,
`merge` изменяет текущий бокс, `extents` возвращает половину размера.
Бокс по умолчанию — точка в начале координат, а не пустой аккумулятор:
при объединении набора начинайте с первого бокса.
Публичные поля позволяют прямую запись; сохранение инвариантов после неё —
ответственность вызывающего кода. Конструкторы проверяют основные условия assert.

## Проверка

Из корня проекта при наличии компилятора и CMake в PATH:

```sh
cmake -S . -B build-math -DBUILD_TESTING=ON
cmake --build build-math --target math_tests_debug math_tests_release
ctest --test-dir build-math --output-on-failure
```

На Windows выбирайте генератор и MinGW согласно своей установке.
Тестовые цели GCC/Clang используют `-Wall -Wextra -Wpedantic -Wconversion
-Wshadow -Werror`. Debug-цель включает assert независимо от конфигурации CMake;
Release-цель задаёт NDEBUG. Проверки тестов работают в обоих режимах.

Без CMake, например в Linux:

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -IGame_/src Game_/tests/math_tests.cpp -o math_tests_debug
./math_tests_debug
g++ -std=c++20 -O2 -DNDEBUG -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -IGame_/src Game_/tests/math_tests.cpp -o math_tests_release
./math_tests_release
```

Подтверждено локально: MinGW GCC 14.2 (Windows x86-64) и GCC 13.3
(Ubuntu WSL x86-64), 107 проверок Debug и 119 Release на каждой платформе.
Полная сборка Windows-клиента также проходит. GCC/ARM64 пока не проверен:
в доступной Ubuntu не обнаружен ARM64-кросс-компилятор.
Переносимость исходников не обещает побитово одинаковых результатов float
между архитектурами и не заменяет сетевую сериализацию.

## Отложено по принятому объёму

Кватернионы — отдельный подэтап до камеры; perspective/ortho/lookAt — этап 7.
Общая инверсия требует отдельного контракта для вырожденных матриц.
Вызываемых заглушек для этих функций нет. SIMD и пересечения не входят в модуль.
